# M5 결과 미리보기 2단계: 관리되는 개발 서버 (제안)

> **이 문서는 제안이다. 현재 동작이 아니다.** 1단계(빌드해서 보기)의 현행 동작은 `docs/architecture.md` "결과 미리보기 → 빌드해서 보기" 절에 있다. 2026-11-27 주인님 질문("React처럼 서버 개념이 필요한 결과물은? VS Code처럼 브라우저를 탑재할 수 있나?")에 대한 아이템 #40 계획의 2단계 설계와, 3단계(에이전트가 미리보기를 도구로 쓰기)와의 연결을 적는다. 코드는 없다.

## 0. 세 단계 요약

| 단계 | 하는 일 | 미리보기가 보는 것 | 네트워크 | 상태 |
| --- | --- | --- | --- | --- |
| 1 | 동의 뒤 `npm run build`, 산출물 폴더를 격리 미리보기로 | 앱이 파일로 내주는 `elsecrew-preview://<토큰>/` | 페이지 전부 차단 | 구현(2026-11-27) |
| 2 | 동의 뒤 `npm run dev`를 앱이 관리, 그 포트만 허용 | 개발 서버 `http://127.0.0.1:<포트>/` | 페이지는 그 포트만. **서버 프로세스는 막지 않음** | 이 문서 |
| 3 | 에이전트가 미리보기를 도구로(스크린샷·콘솔·클릭) | 1·2단계의 같은 뷰 | 1·2단계와 같음 | 7장 연결 계획 |

1단계로 정적 SPA(Vite·CRA 빌드)는 볼 수 있다. 2단계가 필요한 경우는 ① 빌드가 느려 고칠 때마다 다시 빌드하기 어려운 경우(HMR), ② 서버가 있어야 동작하는 결과물(Next.js `next dev`, API 라우트, SSR), ③ 개발 서버가 주는 오류 오버레이가 필요한 경우다.

## 1. 목표와 범위

- 목표: 사용자가 동의하면 앱이 작업 공간에서 개발 서버를 띄우고, 미리보기 탭이 그 서버를 보여 준다. 코드를 고치면(팀이든 사용자든) HMR로 화면이 바로 바뀐다.
- 범위: macOS, npm·pnpm·yarn의 `dev` 스크립트, Vite·Next.js·CRA(webpack-dev-server)·Astro처럼 `--port`/`PORT`를 받는 도구.
- 비목표: 서버 프로세스의 네트워크 격리(OS 샌드박스 없이 불가능), 원격 접속·터널, 여러 서버를 묶는 구성(docker compose), Windows(1단계와 같이 미검증).

## 2. 1단계와 달라지는 것

| 항목 | 1단계(빌드) | 2단계(개발 서버) |
| --- | --- | --- |
| 프로세스 수명 | 끝나는 일 | 탭을 보는 동안 계속 도는 서버 |
| 페이지 출처 | 앱 스킴, 앱이 파일을 하나씩 내줌 | 서버가 직접 답하는 `http://127.0.0.1:<포트>` |
| 응답 헤더 | 앱이 고정(CSP·nosniff·no-store) | 서버가 정함 → 앱이 `onHeadersReceived`로 덧씌움 |
| 네트워크 허용 | 자기 출처만(스킴) | 그 포트의 `http:`·`ws:`만 |
| 서비스 워커 | 스킴 특권으로 불가 | `127.0.0.1`은 안전한 출처라 가능 → 막아야 함(T-D13) |
| 작업 공간 쓰기 | 빌드 산출물 | 도구 캐시(`node_modules/.vite`, `.next`) — Git 무시 확인 필요 |

## 3. 구조

### 3.1 실행 (main 소유, 1단계 `PreviewBuildManagerV1` 확장)

- 계획: sidecar `preview.buildPlan`에 `devScript`(문자열·없음)와 `devTool`(`vite|next|cra|astro|unknown`, package.json 의존성으로 판단)을 더한다. 읽기 전용·채팅 바인딩 기준은 같다. Next.js는 `.next/`, Vite는 `node_modules/.vite`가 Git 무시인지도 확인한다.
- 포트: **main이 고른다.** 41000~41999에서 `127.0.0.1`에 bind 해 보고 비어 있는 포트를 정해 명령에 넣는다. 앱 개발 서버·CDP 포트(실행 인자로 알 수 있는 것)는 제외한다.
  - Vite·Astro: `npm run dev -- --host 127.0.0.1 --port <p> --strictPort`
  - Next.js: `npm run dev -- -H 127.0.0.1 -p <p>`
  - CRA: 환경 `HOST=127.0.0.1 PORT=<p> BROWSER=none`
  - 알 수 없는 도구: `HOST`·`PORT` 환경만 주고, 출력의 첫 `http://(127.0.0.1|localhost):<n>` 주소를 후보로만 쓴다(아래 확인을 통과해야 함).
- **포트 확인(필수)**: 미리보기를 열기 전과 다시 연결할 때마다, 그 포트에서 LISTEN 중인 소켓의 소유 프로세스가 **이 서버의 프로세스 그룹** 안에 있고 주소가 루프백인지 확인한다(macOS `lsof -nP -a -iTCP:<p> -sTCP:LISTEN -g <pgid>` 또는 `proc_pidfdinfo`). 아니면 열지 않는다(T-D4, T-D7). 0.0.0.0·`::`에 bind 했으면 "이 컴퓨터 밖에서도 접속될 수 있어 멈췄어요"로 즉시 멈춘다.
- 동의: 시작마다 main 기본 대화상자. 명령 전체(포트 인자 포함)·프로그램·위치·"멈출 때까지 이 컴퓨터에서 계속 실행돼요. 페이지는 인터넷이 막혀 있지만 서버 프로그램은 막지 않아요"를 보인다. "이 작업 동안 다시 묻지 않기"는 열린 결정(8장).
- 수명
  - 작업당 하나, 전체 둘(빌드와 합산할지 열린 결정).
  - 미리보기 탭을 떠나 10분, 작업 전환, 앱 화면 새로고침, 창 닫힘, 종료 준비·종료 → 그룹 종료(SIGTERM, 3초 뒤 SIGKILL). 1단계와 같은 코드 경로.
  - 앱이 비정상 종료한 뒤: 시작 때 지난 실행 기록(pgid·시작 시각·명령 해시, 앱 데이터)을 보고, 그 pgid의 리더가 같은 시작 시각이면 그룹을 끝낸다. 다른 프로세스면 건드리지 않는다(자기 PID만 원칙).
  - 서버가 스스로 죽으면 탭에 "개발 서버가 멈췄어요 · 다시 시작"과 마지막 로그.
- 로그: 1단계와 같은 가림·상한·저장. HMR 갱신 줄이 많으므로 같은 줄 반복은 접어서 센다.

### 3.2 미리보기 네트워크 정책 (`source: "devServer"`)

새 원본 종류만 더하고, 뷰·세션 생성 순서·권한 거절·가림 처리(T16)·토큰 partition은 1단계 그대로 쓴다.

- 출처: `http://127.0.0.1:<p>` 한 개. `localhost`는 쓰지 않는다(IPv6 `::1`·DNS 우회 방지).
- `webRequest.onBeforeRequest`: 그 출처의 `http:`와 `ws:`(HMR), `data:`, 같은 출처 `blob:`만 통과. 다른 포트·다른 호스트·`https:`는 취소.
- 프록시: `fixed_servers 127.0.0.1:9`(무효)는 유지하고 `proxyBypassRules: "127.0.0.1:<p>"`(그 호스트:포트만 직접 연결). `<-loopback>` 규칙과의 결합을 실제 net log로 확인해야 한다(검토 지점 1).
- 헤더 덧씌우기(`onHeadersReceived`): `Content-Security-Policy`에 `connect-src 'self' ws://127.0.0.1:<p>`, `frame-src 'self'`, `form-action 'self'`, `worker-src 'self' blob:`를 **추가**한다(서버의 CSP가 더 엄하면 둘 다 적용됨). `Service-Worker-Allowed` 제거. `Set-Cookie`는 그대로(메모리 partition).
- 서비스 워커: 세션의 `serviceWorkers` 등록을 막는다. Electron에 직접 끄는 API가 없으면 `onBeforeRequest`에서 `resourceType === "serviceWorker"`(스크립트 가져오기)를 취소한다(검토 지점 2).
- 탐색: 같은 출처만. 서버가 다른 포트로 리디렉트하면 막고 알린다.
- 앱 틀: "미리보기 — 개발 서버" + "서버 실행 중"(멈추기 단추) + "페이지 인터넷 차단". 1단계의 "읽기 전용"은 빼고, 서버가 작업 공간에 쓸 수 있다는 것을 문구로 밝힌다.

### 3.3 HMR

- Vite HMR은 같은 포트의 WebSocket(`vite-hmr` 서브프로토콜)이다. `ws://127.0.0.1:<p>/`만 허용하면 된다. `server.hmr.port`를 따로 정한 프로젝트는 그 포트가 다르므로 HMR만 동작하지 않는다(페이지는 보임). 1차에는 수용하고, 계획 단계에서 vite.config의 `hmr.port`를 읽으면 경고를 띄운다.
- Next.js `next dev`도 같은 포트의 `/_next/webpack-hmr`(WebSocket).
- 앱의 "새 결과" 띠는 개발 서버 원본에서는 띄우지 않는다(HMR이 대신함).

## 5. 독립 검토가 필요한 지점

1. 프록시 우회 규칙(`127.0.0.1:<p>`)과 `<-loopback>`의 결합이 그 포트만 직접 연결하는지 — net log로 다른 루프백 포트·IPv6 루프백이 무효 프록시로 가는지 확인(T-D1).
2. 서비스 워커 차단 방법과 Electron 43에서의 실제 동작(T-D13).
3. LISTEN 소유자 확인 구현(그룹·주소 판단, 확인과 연결 사이 틈)(T-D4·T-D7).
4. 고아 서버 정리의 신원 판단(pgid·시작 시각) — 남의 프로세스를 끝내지 않는지(T-D5).
5. 동의 문구가 "서버는 인터넷을 막지 않는다"를 비개발자에게 정확히 전하는지(T-D2).

## 6. 시험 계획

- 단위(TS): 포트 고르기·명령 인자 표·LISTEN 판정·헤더 덧씌우기·webRequest 판정(포트·호스트·스킴 조합).
- 매니저(가짜 프로세스): 시작·멈춤·작업 전환·화면 새로고침·종료·고아 정리, 포트 확인 실패 시 열지 않음.
- 실제 Electron 격리 프로브(`m5:test:preview-isolation` 확장): 개발 서버 원본으로 T1~T3·T-D1·T-D8·T-D13 net log 판정, 수집 서버 접속 0.
- 실제 앱: Vite+React todo로 시작 → 미리보기 → 파일 수정 → HMR로 화면 바뀜 → 탭 떠남 → 10분 뒤(시험은 짧게) 멈춤 → ps로 그룹 0.

## 7. 3단계(에이전트가 미리보기를 도구로)와의 연결

목표: 팀의 에이전트가 자기가 만든 화면을 직접 보고 고친다. 1·2단계의 같은 격리 뷰를 쓰고, **에이전트는 새 권한을 얻지 않는다**.

- 도구 세 가지(엔진이 공급자에게 주는 앱 도구, MCP 형태 후보)
  - `preview_screenshot`: 미리보기 페이지 캡처(JPEG, 긴 변 1280px·1MiB 상한). main `capturePage`.
  - `preview_console`: 미리보기 페이지의 콘솔 오류·경고(가림 적용, 최근 200줄·64KiB 상한). main `console-message` 수집.
  - `preview_click` / `preview_type`: 선택자나 좌표로 클릭·입력. main `sendInputEvent`(1단계 실제 앱 시험에서 쓴 방식).
- 경로: 공급자 도구 호출 → sidecar(도구 요청 기록·승인 정책) → main 미리보기 관리자 → 결과. 토큰·작업 공간 경로는 여전히 main 밖으로 나가지 않는다.
- 동의
  - 빌드·설치·개발 서버 시작은 지금처럼 **사람이 main 대화상자에서** 동의한다. 에이전트가 시작을 원하면 승인 카드("미리보기를 위해 빌드할게요")로 요청하고, 사람의 허용이 main 대화상자로 이어진다. 에이전트가 직접 명령을 실행하는 권한과는 별개다.
  - 이미 열린 미리보기를 보는 도구(스크린샷·콘솔)는 작업 권한(`workspaceWrite` 이상) 안에서 자동, 클릭·입력은 프로젝트 설정으로 끌 수 있게 한다(열린 결정).
- 화면 밖에서 보기: 사람이 미리보기 탭을 보고 있지 않을 때 에이전트가 쓰려면 화면에 붙지 않은(offscreen) 뷰가 필요하다. 같은 세션 설정 함수를 쓰고 `WebContentsView`를 창에 붙이지 않는 모드를 더한다. 사람이 탭을 열면 같은 인스턴스를 붙인다.
- 1·2단계에서 미리 맞춰 둘 것
  - 미리보기 관리자의 "열기"가 화면 배치(`bounds`) 없이도 가능하게(offscreen) 나누기 쉬운 구조 — 지금은 `#open`이 측정을 먼저 요구한다.
  - 콘솔 수집을 1단계 뷰에도 넣되 IPC로는 내보내지 않기(프로브용 `denials`처럼).
  - 빌드 로그 계약(`PreviewBuildJobViewV1`)을 에이전트 도구 결과로도 재사용.

## 8. 구현 순서와 열린 결정

1. 계획 확장(sidecar `devScript`·`devTool`·캐시 무시 확인) → 2. 포트·명령 정책과 LISTEN 확인(main 순수 함수) → 3. 매니저 수명(1단계 확장) → 4. 미리보기 `source: "devServer"`(세션 정책·헤더) → 5. 실제 격리 프로브 → 6. 화면(틀 문구·멈추기·로그) → 7. 독립 검토 → 8. 3단계 도구.

열린 결정
- 개발 서버 동의를 "이 작업 동안 다시 묻지 않기"로 줄일지(편의 vs. 매번 확인).
- 빌드와 개발 서버의 동시 실행 상한을 합칠지.
- 알 수 없는 도구(`HOST`/`PORT`를 무시하는 서버)를 허용할지, 출력 주소 감지로만 열지.
- 3단계 클릭·입력 도구의 기본값(켜짐/꺼짐).
