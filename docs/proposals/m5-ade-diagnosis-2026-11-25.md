## 3. 디자인 방향 후보

세 시안 모두 다음 공통 원칙을 지킵니다.

- 편집기를 주인공에서 내립니다.
- 상태 기계 하나로 모든 표시를 일치시킵니다.
- 강조색은 "지금 할 일 하나"에만 씁니다.
- 비개발자 문구를 씁니다.

목업은 `mockups/*.html`이고, 렌더 이미지는 `mockups/*.png`(1440×900)입니다. 특정 제품의 외형을 따르지 않았습니다.

### 방향 A — 작업 관제실 (Mission Control) · `mockups/direction-a-mission-control.png`

**컨셉.** 화면 가운데를 '지금 진행 중인 작업 하나의 이야기'에 줍니다. 위에는 단계 진행 막대(계획 → 개발 → 검증 → 정리)가 있습니다. 그 아래 팀원 카드에는 각자 무엇을 했는지 요약, 바뀐 파일, 되돌리기가 붙습니다. 지금 일하는 팀원은 실시간 활동 줄을 펼쳐 보여 주고, 확인이 필요하면 노란 카드가 흐름 안에 끼어듭니다.

**핵심 화면 구성.**

- 왼쪽: 모든 프로젝트의 작업을 상태별로 묶은 목록(지금 일하는 중 / 검토 기다림 / 끝남)
- 가운데: 목표, 단계 막대, 팀원 카드, 확인 요청, 진행 중에도 쓸 수 있는 입력칸과 멈춤·중단
- 오른쪽: 미리보기 · 변경 · 파일 · 기록 탭과 "내 폴더에 넣기"
- 상단: 작업 사용량·소요 시간, ⌘K·⌘N 안내

**장점.**

- 현재 구조(3단)에서 가장 적게 바꾸고 D1·D2·D3·F1·F4를 한 번에 해결합니다.
- 단계 커밋이 이미 있어 "이 단계 되돌리기"와 붙이기 쉽습니다.

**단점.**

- 병렬 작업 비교(F2)는 목록 수준에 그칩니다.
- 오른쪽 패널이 여전히 좁아 diff를 길게 읽기에는 부족합니다(전체 화면 전환 필요).

### 방향 B — 작업 보드 (Task Board) · `mockups/direction-b-task-board.png`

**컨셉.** 첫 화면을 모든 프로젝트·작업의 보드(확인 필요 / 진행 중 / 검토 기다림 / 내 폴더에 들어감)로 삼습니다. 카드에는 단계 진행 막대와 "지금 무엇을 하는지" 한 줄이 붙습니다. 같은 목표를 두 시안(다른 에이전트나 모델)으로 돌려 나란히 비교하고, 고른 쪽만 넣습니다. 카드를 열면 방향 A의 작업 상세로 들어갑니다.

**핵심 화면 구성.**

- 상단: 프로젝트 필터, 상태 요약, 새 작업
- 보드 4열
- 하단 또는 별도 화면: 시안 비교(미리보기, 사용량, 소요 시간)

**장점.**

- 여러 프로젝트를 돌리는 사용자에게 가장 ADE다운 첫인상을 줍니다.
- "확인 필요"가 맨 앞 열이라 놓치지 않습니다.
- 라이트 테마 시안을 겸합니다.

**단점.**

- 작업 상세 화면(A)이 따로 필요해 총 작업량이 가장 큽니다.
- 백엔드의 동시 실행·자원 한도 정책을 먼저 정해야 합니다(F2 확인 필요).
- 작업이 한두 개뿐인 초보자에게는 빈 열이 많아 보입니다.

### 방향 C — 대화 + 결과 캔버스 · `mockups/direction-c-result-canvas.png`

**컨셉.** 비개발자에게는 코드보다 결과물이 중요하다는 데서 출발합니다. 왼쪽은 대화이고, 계획 체크리스트와 단계 칩이 포함됩니다. 오른쪽 넓은 캔버스는 에이전트가 만든 앱의 미리보기를 넓은 화면과 좁은 화면으로 나란히 보여 줍니다. 바뀐 곳에는 번호 핀을 꽂고, 핀마다 "좋아요 / 더 크게 / 이 부분만 되돌리기"로 반응합니다. 코드 diff는 '바뀐 점' 탭으로 내려갑니다.

**핵심 화면 구성.**

- 왼쪽 대화(약 420px)
- 오른쪽 캔버스: 결과 미리보기 · 바뀐 점 · 계획 문서 · 기록 탭, 넓게/좁게/다시 실행
- 하단: 검증 요약과 "내 폴더에 넣기"

**장점.**

- 제품 정체성("비개발자의 개발 팀")에 가장 맞습니다.
- 실제 화면을 아무도 확인하지 못하는 F12 문제를 사용자 쪽에서 해결합니다.
- 피드백이 구체적이 됩니다(핀 + 말).

**단점.**

- 웹 결과물이 아닌 프로젝트(스크립트, CLI)에서는 캔버스가 비어 대체 화면이 필요합니다.
- 미리보기 격리(네트워크·파일 접근) 설계가 선행돼야 합니다.
- 핀 → 코드 위치 매핑은 어렵습니다(1차는 "바뀐 파일" 수준).

### 추천

**A를 뼈대로 삼고, 오른쪽 패널 첫 탭에 C의 결과 미리보기를 넣고, 왼쪽 목록을 B의 상태별 묶음으로** 시작하기를 권합니다. B의 보드와 시안 비교는 2~3차에서 A의 왼쪽 목록을 "보드로 펼치기"로 확장하면 됩니다.
